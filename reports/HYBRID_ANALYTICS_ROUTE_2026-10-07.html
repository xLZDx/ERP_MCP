Summary

One read-only tool was added: accounting_balance_by_analytics(source_id, company_id, as_of). It returns balances of the profile-approved accounts split by up to three analytics slots (counterparty, contract, item, warehouse and so on).

The route is chosen before execution and only from persisted evidence: OData Balance when available; a separate local COM bridge only when OData is proven unsupported and an exactly matching approved binding exists; unknown or drifted state fails closed. There is no automatic switch from OData to COM after an error.

Verified: ruff clean; full non-e2e suite 1769 passed, 182 skipped; hosted CI of PR #21 on head 368f4fa: test, windows-rsv-privacy, odata-upstream, release-evidence all success.

Live parity proof (disposable clone, read-only, reference clone never opened): the OData publication erp_mcp_probe and COM on the same database (the publication descriptor path equals the COM clone path): 21 of 21 rows equal, identical hashes, database unchanged during the run.

End-to-end run

The public tool was run end to end on the disposable clone, read-only: tool → adapter → real sidecar → GET/HEAD-only proxy → real Apache publication (OData leg), and tool → client → real bridge → real COM (COM leg; the OData capability was forced to unsupported because the real base answers available, so this leg proves the wiring, not the route decision). Registry and audit were test fakes; the mappings were built from live keys.

What the live checks caught

  • The COM connector has no Type() method: a reference is built through TypeDescription(...).Types().Get(0) and XMLValue. Fixed in the bridge and the test fake.
  • Real publication descriptors write the path unquoted (ib="File=D:\...;"); the parity-proof parser was fixed and a regression test added.

Review findings closed

  • MAJOR: OData rows without the company property were accepted and the COM route had no per-row company check. The property is now required, the bridge selects the organization and fails closed on another one, and the gateway compares it again.
  • MAJOR: after a timeout the COM query could still run inside 1C while the next request opened a second session, and a slow binding could occupy the shared thread pool. The binding is now poisoned until the abandoned query returns and at most two requests per binding are admitted.
  • MAJOR (tests): swapping the internal company id for the external reference, drift on the COM branch, provenance per field, factory and binding call counts and the fingerprint clause of the harness each now have an assertion that fails on mutation.
  • MINOR: a full page is always reported truncated; strict amount parsing; success audit written after the response is built; locked COM client creation; canonical company reference; as_of limited to 1990-2100; body cap on Content-Length; the COM route refuses a mapping the bridge does not serve.
