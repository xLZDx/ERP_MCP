# Просьба бухгалтеру: отчёты 1С для подтверждения профиля (818 HA)

Зачем: пока профиль реального источника не подтверждён, плагин в ChatGPT не отвечает на вопросы про остатки, обороты и
кредиторку (`SEMANTIC_PROFILE_UNVALIDATED`). Подтверждает профиль только человек: нужны не меньше десяти настоящих отчётов
из клиента 1С, снятых с экрана. Автоматически созданные отчёты не засчитываются. Полный регламент:
`docs/NATIVE_REPORT_CAPTURE_RUNBOOK.md`.

## Что сделать (по одному отчёту на кейс)

1. Откройте базу 818 HA (копия на 2026-09-15), период 2026-08-01..2026-08-31.
2. Для каждого кейса из таблицы запустите указанный отчёт в клиенте 1С и выгрузите его в XLSX или MXL.
3. Положите файл в папку `D:\ERP_MCP_Testbed\1c\reference\native_reports\captures\<номер кейса>\` под именем `native_report.xlsx`.
4. Посчитайте хэш: `Get-FileHash -Algorithm SHA256 <файл>`.
5. Впишите в `D:\ERP_MCP_Testbed\1c\reference\native_reports\native-evidence.TEMPLATE.json` для кейса: `report_name` (как в клиенте),
   `generated_at` (время из клиента), `native_report_sha256`, `signed_by`, и поставьте `status` в `PASS`, только если цифра
   отчёта совпала с ответом шлюза. Иначе `FAIL` или `INCONCLUSIVE`. Не используйте ответ шлюза как ожидаемое значение.

## Кейсы

| Кейс | Что подтверждаем | Какой отчёт запустить в 1С |
|---|---|---|
| NR-01 | Итог закрытия месяца | Оборотно-сальдовая ведомость и регламентные операции закрытия |
| NR-02 | Остаток по счёту 216.1 на 31.08 | Карточка счёта или ОСВ по 216.1 |
| NR-03 | Оборот по счёту 811.1 за август | Карточка счёта 811.1 |
| NR-04 | Оборот по счёту 821 за август | Карточка счёта 821 с разбивкой распределения затрат |
| NR-05 | Отрицательные остатки по счёту 211 | ОСВ по номенклатуре и складам |
| NR-06 | Позиции по 211 без движения в августе | Движения по номенклатуре и складам за август |
| NR-07 | Остаток кассы 241.1 и знак на конец дня | Кассовая книга или карточка счёта по кассам и дням |
| NR-08 | 21 переданный счёт-фактура найден | Документы покупки и поступления, книга покупок НДС |
| NR-09 | Платежи без документов поступления | Банк, авансовые отчёты, документы покупки |
| NR-10 | Поступления 31.08 без первичных документов | Реестр поступлений за 2026-08-31 |
| **NR-11** | **Расчёты с поставщиками по счёту 521.1 на 31.08** | ОСВ или карточка счёта 521.1 по контрагентам и договорам |

NR-11 добавлен инженерами: десять обязательных кейсов не покрывают счёт 521, а именно на нём строится вопрос «сколько мы должны
каждому поставщику». Он нужен сверх десяти, один и тот же профиль подтверждает все кейсы вместе.

## Что делаем после этого

Оператор запускает `scripts/semantic_profiles.py validate --profile-id <id> --evidence-file native-evidence.json --actor <id>`.
Проверка требует десять различных `PASS` с хэшем. Решение по сопоставлению счетов остаётся за оператором. Остатки и обороты по
счёту 521.1 отдаёт инструмент `accounting_balance_by_analytics`; инструмент `payable_balance` для этой базы не подходит, потому что
в конфигурации нет регистра накопления расчётов с контрагентами (расчёты с поставщиками ведутся на счёте 521).
