## Scope and evidence

This continuation covers the existing private standard-report runner under scripts/real1c/native_engine_reports.py. It retains the fixed report and COM operation allowlists, fixed reader, disposable clone, permission checks, preflight and before/after fingerprint gates. It introduces no new credentials, write grants, runtime route, user-supplied path, or external processing capability.

| Criterion | Bounded acceptance | Verification |

| TC067: native report provenance | Identify the allowlisted standard configuration object and data-composition route using wrapper-owned values. Bind generated output to its existing byte digest and the run manifest's reader, period, clone and fingerprint context. Report content fingerprints are not made stronger by the new metadata. | Inspect a synthetic run manifest and trace the fake COM calls to the allowlisted object's Create operation. | TC068: empty COM output has no balance | A result with zero rows or columns is EMPTY, has no exported bytes or digest and contributes no numeric result. A report error is UNAVAILABLE. | Cover each zero-dimension case, preserving the distinction from a successfully generated document. |
| TC069: untrusted external processing is denied | The call and object vocabulary exposes no external processing loader. A report identifier or external processing file name outside the standard report allowlist is rejected before clone creation, credential access or COM connection. | Assert an external processing file name is rejected before any runtime call and the external processing loader is outside the COM call allowlist. |

Only the existing runner and its named synthetic test module are in scope. Native engine evidence remains comparison-only. Full native qualification requires actual standard report output from an authorized clone, the exact configuration identity and independent accountant/UI evidence for profile validation. Those product checks remain in the backlog if unavailable.

## Concurrency, retry and failure

The runner copies to a fresh disposable clone for each timestamp, using a copy operation that refuses an existing destination. It derives a private output directory from the same timestamp. A duplicate timestamp cannot share a clone. The proposed provenance adds no new execution or retry path. A failure before export has no digest; a partial export without a valid recorded run manifest is not evidence. Missing provenance on old manifests must not upgrade their evidence class. The wrapper continues to refuse unknown COM operations and unavailable or changed clone state.
