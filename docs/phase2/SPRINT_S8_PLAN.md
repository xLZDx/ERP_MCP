## Scope decision

S8 builds only what can be built and tested OFFLINE, as unwired, in-memory, synchronous reference modules (all NEW files; existing modules are touched only for a defect proven by a failing test, same rule as S6 E3, S6b and S7). The deliverable is the presentation MODEL and the API DECISION logic: pure functions that turn existing run/attestation/coverage/time records into view models with fixed labels and into fixed accept/refuse decisions. There is no HTML, no JavaScript, no browser, no web framework, no HTTP server, no cookie handling, no DB and no 1C. "UI explanation" in S8 means a typed, frozen view-model whose fields and fixed label enums a future UI must render verbatim; whether a human actually understands it is G5 UAT and stays operator-owned.

Design decisions fixed here (so reviewers can falsify them):

1. Views are derived, never authoritative. Every view model is a frozen dataclass computed from existing immutable records at a given injected "now"; it holds no state a caller can edit, and its `authority` is `EVALUATION_ONLY`. A view cannot set a status: there is no function that accepts a verdict, state, `VALIDATED` or numbers from the caller (R2-REQ-26 "no API that sets VALIDATED from arbitrary JSON"). Reviewer notes are a separate append-only annotation log keyed by run id and never alter, hide or re-total the original numbers.
2. Original numbers are immutable by construction and by check (TC116). The discrepancy card carries the numbers exactly as stored in `RunRecord.native_values`/`gateway_values` (exact `Decimal`) and an `original_digest = canonical_digest(...)` over tenant, run id, snapshot digest and both value tuples. `verify_original(card, ledger)` recomputes it from the ledger and reports `ORIGINAL_INTACT` or `ORIGINAL_TAMPERED`. The workbench API surface has no parameter named like a number override; annotation text is length-bounded text, never parsed as a number, and an "adjustment"/"override" request is refused with `ORIGINAL_NUMBERS_IMMUTABLE`.
3. Delta is computed, not stored: `delta = gateway - native` as exact `Decimal` in a fixed-precision local context (same `_EXACT` approach as `comparison_snapshot.py`); precision overflow gives the fixed reason `DELTA_PRECISION_EXCEEDED` and no card, never a rounded delta. Row/fragment/owner linkage (TC115): a card names the measure key (`RunRecord.differences` entries) and, when the adapter supplies a `Comparison`, the `row_key` (counterparty_ref, contract_ref) and `measure`; the fragment is a reference `(snapshot_digest, row_key, measure)` into the frozen snapshot, never the raw document; the owner comes from an injected owner directory `(tenant, company, source)` -> `owner_id` and an unmapped item gets `OWNER_UNASSIGNED` (visible, never a guessed owner, never "everyone"). The adapter that maps `Comparison` rows to cards is explicit; a run recorded only as key names (the `RunLedger` shape) yields measure-level cards with `row_key=None` and the honest label `ROW_DETAIL_UNAVAILABLE`.
4. New evidence means a NEW run (TC117). `request_rerun(...)` accepts typed ids only (comparison key, previous run id, NEW snapshot id) and delegates to `RunLedger.run(..., rerun_of=previous)`; it first refuses a snapshot id/digest identical to the previous run's (`NO_NEW_EVIDENCE`), a previous run that is not the chain head or is already superseded (`RERUN_TARGET_STALE`), and a foreign tenant (`NOT_IN_SCOPE`). The old run stays readable as SUPERSEDED with its original numbers; the new run is a new record with `supersedes` set. A backdated correction is therefore a new run, not an edit. An INCONCLUSIVE rerun never hides the last decisive CURRENT run (existing `RunLedger` rule, asserted at the view level).
5. Two time axes are separate labelled fields (TC118). Every timeline entry carries `known_at` (when the system recorded/knew it, from `recorded_at`/`known_at`) as `KnownTimeLabel` and `effective_at` (source-effective validity) as `EffectiveTimeLabel`; a missing effective time is the explicit label `EFFECTIVE_UNKNOWN`, never filled from known time, observed time or "now". The two fields have different type names so they cannot be swapped silently, the rendered label strings are fixed constants (`KNOWN_AT`, `EFFECTIVE_AT`), and an entry never exposes a single ambiguous "date".
6. Applicability is computed, and "green" is scarce (TC119). A fixed `Applicability` enum: `LIVE_CURRENT` (the only value that may render green), `HISTORICAL_PASS` (was PASS, not current: superseded run, newer revision, newer snapshot, or older than the freshness window), `REVOKED` (attestation revoked: history kept, current applicability removed), `UNATTESTED`, `INCONCLUSIVE`, `FAIL`, `NOT_COVERED`, `UNKNOWN`. `LIVE_CURRENT` requires ALL of: run is `CURRENT` per `RunLedger`; the attestation passes `AttestationStore.check_current` (code `VALID`; `check_as_of` is never used for a gate); coverage `MatrixResult.accepted`; freshness within an injected policy window on the injected clock; and the source is not paused/quarantined/revoked. Any missing input is a downgrade to a named non-green value, never a default green; `PASS` with an unknown input downgrades to `UNKNOWN`. A `HISTORICAL_PASS` entry carries the label text "historical, not current" and the reason (`SUPERSEDED_BY_RUN`, `REVISION_CHANGED`, `ATTESTATION_REVOKED`, `STALE`, `SOURCE_PAUSED`); the view layer provides `is_green(entry)` as the single source of truth and a test asserts that no non-`LIVE_CURRENT` entry returns true.
7. Scope is enforced in the view builder, not by the renderer (TC120). Every builder takes a `ViewerScope(tenant_id, company_id, scope_epoch)` and an injected `ScopeAuthority` snapshot of the current epoch; entries and evidence outside the viewer's (tenant, company) are DROPPED and counted only as a fixed `HIDDEN_BY_SCOPE` flag (no count, no ids, no names, so existence is not disclosed); a stale epoch gives `SCOPE_EPOCH_STALE` and no view (reauthorization before disclosure, revoke before disclosure, same rule as TC014). Diff and evidence panels show only data resolved inside that scope; a cross-company evidence link is not rendered even as an id.
8. Safe errors are a closed vocabulary (TC121). `SafeError` = `(reason_code: ReasonCode, next_action: NextAction, correlation_id)`; both enums are fixed, `correlation_id` is generated by an injected id source (deterministic in tests) and never derived from input. The renderer maps each reason code to a fixed message from a constant table; it takes no free text, no exception object, no foreign source name, stack trace, secret reference, SQL fragment or provider text. A test feeds hostile "poison" strings and exception objects into every public error path and asserts the poison is absent from every output field and from `repr`.
9. Job/result API is a decision layer, not a server (TC121-123). `jobs_api.py` models the decision of the control-plane endpoints as pure functions over typed requests: `decide_enqueue` (rescan/report/reconciliation), `read_job`, `read_result`, `decide_rerun`, and the operation annotation table. Each endpoint has a fixed annotation record `(read_only: bool, destructive: bool, idempotent: bool, open_world: bool)`: enqueue/rerun/pause/revoke are `read_only=False` (control mutations even though the source is read-only, per `CONTRACTS_AND_API_RU.md`: "source read-only does not make enqueue non-mutating"), `destructive=False`, `idempotent=True`; reads are `read_only=True`. A test fails if a mutating endpoint is annotated read-only or if an endpoint is missing from the table.
10. CSRF and idempotency are modelled as deterministic decisions (TC122). CSRF: a session record holds a server-side CSRF secret digest; the decision compares the presented token in constant time to the expected value derived from the session by an injected pure derivation (no randomness; tokens in tests carry a `FAKE-` prefix); missing, wrong, other-session, expired-session or token-from-another-tenant gives HTTP-like class `403` with `CSRF_REJECTED`. This covers cookie-authenticated admin mutations only; a safe-method read needs no token. Idempotency: the key is scoped by `(tenant, actor, operation)`; the store records `request_digest = canonical_digest(typed params)`; same key + same digest returns the original outcome as `REPLAYED` (no second job, no second audit "effect" entry); same key + different digest is `409 IDEMPOTENCY_CONFLICT` and the stored outcome is untouched; a missing/oversized/ill-formed key on a mutation is refused `IDEMPOTENCY_KEY_REQUIRED`; keys are bounded in count and age on the injected clock (eviction is explicit and never reuses a key for a different digest within the retention window). Order of checks is fixed and tested: authentication/session -> CSRF -> scope/epoch -> operation boundary -> idempotency -> enqueue; a CSRF failure never consumes or creates an idempotency record.
11. A refusal cannot be bypassed by another spelling or channel (TC123). The API accepts only typed ids and a registered parameter schema; it has no free-form "command", "query", "sql", "onec_code" or "raw" parameter anywhere (AST-checked signatures and dataclass fields). Any operation name is run through `canonical_operation` and `side_effect_boundary.evaluate`; a name that is not in the registry is `UNCLASSIFIED` and denied; a refused (scope, operation) pair is written to an append-only `RefusalLog` and the same request re-submitted with different casing, whitespace, unicode lookalikes or a different channel label (`COM`, `DC`, `HTTP`, `MCP`) is refused with the SAME fixed code and never reaches the fake dispatcher (call log asserts zero calls). Channel is not an input to the decision: the decision function has no channel parameter, so a raw COM/DC path cannot receive a different answer; the boundary test also asserts that no S8 module imports a COM/DC/1C client.
12. Safe rerun is idempotent and fenced by state (TC117, TC122). `decide_rerun` is a mutation: it requires CSRF + idempotency, a typed previous run id that is still the chain head, a new snapshot, and an authorized actor; it returns a `JobTicket` (typed ids, request digest) and does not itself call 1C or compute numbers (the run is produced by the existing `RunLedger.run` through the offline fake in tests). A rerun on a paused/revoked source is refused with the fixed code; a rerun never deletes or edits the original run.
13. Capture default stays OFF in prod and S8 adds no permit logic: an enqueue for a capture-type job is allowed to proceed to the fake dispatcher only if the existing `capture_permit.py` decision (passed in as a typed allow/deny fact) allows it; absence or expiry refuses. S8 does not open any capability and does not call `validation_coverage.capability_enabled` to enable anything - it only reads coverage.
14. Honest limits stay in the output: every view and decision carries `authority="EVALUATION_ONLY"` and a `basis` text constant that says the data are scripted/offline when produced over fakes; no module can produce a value that reads as native PASS, VALIDATED or production-ready.

## Known gaps stated up front (honest limits, not hidden)

- The offline run model (`RunRecord.differences`) holds measure keys only; row-level `Difference(row_key, measure, expected, actual)` exists in `reconciliation.Comparison`, which `RunLedger` does not persist. S8 bridges this through an explicit adapter and the label `ROW_DETAIL_UNAVAILABLE`; persisting row-level differences in the run ledger would be an edit to `comparison_snapshot.py` and is a follow-up (not done in S8 unless a failing test proves it required for TC115).
- `ports.JobQueuePort` is async and SQL-backed; S8's synchronous in-memory idempotency/job decisions do not call it and are not proven against the real `jobs` table or its `idempotency_key`/`request_digest` constraints. The adapter and a PostgreSQL integration are a follow-up and NOT_RUN.
- Freshness windows, owner directory, session and CSRF derivation are injected fakes; the real session store, cookie flags, SameSite policy, token rotation and CORS are not modelled.
- Display strings are fixed constants, not localized RU/EN UI text; localization, layout and accessibility are not addressed.
- Authorization of the actor (role model: accountant vs auditor vs admin vs API engineer, operations separation) is modelled only as an injected allow/deny fact; the real role/RBAC wiring is not built.
