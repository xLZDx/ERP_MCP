# ERP_MCP Phase 2 — Data and API Contracts: TDD Clarification

**October 8, 2026 · v0.1 · DRAFT FOR REVIEW.** This is a design proposal, not an executed database migration or a list of currently available MCP tools.

## 1. Data Groups

| Group | Proposed entities | Boundary |
| --- | --- | --- |
| **Connections** | `connector_instances`, `scope_memberships`, `provider_principals` | Reuse existing source/company authority; store secret references, **not** secret values |
| **Jobs** | `jobs`, `leases`, `cursors`, `outbox` | Scope, idempotency and parameter digest; fencing; atomic page/cursor/outbox |
| **Physical Data Model (PDM)** | `snapshots`, object/field/relation versions | Keep raw and canonical hashes separate; pin canonicalizer version and coverage |
| **Accepted state** | `accepted_heads`, `acceptance_events` | CAS, independent actor/policy/evidence; scanner is **not** the approver |
| **Logical Data Model (LDM)** | `concepts`, `aliases`, typed/dependency edges | Stable IDs; source/company scope; provenance, confidence and owner |
| **Time** | Immutable `model_events`, current projections | Known/effective time, corrections, supersedes, gaps, deterministic replay |
| **Capture** | `recipes`, `qualifications`, `execution_permits`, `job_events` | Source/config/report/variant/executor hash; mode, time window and budget |
| **Evidence** | `artifacts`, `revisions`, origin checks, `attestations` | Private immutable bytes, actual digest, authenticated signer, scoped foreign keys |
| **Reconciliation** | `runs`, `measures`, row links, discrepancies | Exact scope/cutoff/model/parser/recipe/policy pin; numerical vs business acceptance |
| **Validation** | `policies`, operation bindings, evidence claims | Actual evidence foreign keys and coverage; no arbitrary JSON `VALIDATED` flag |

Source-wide PDM may be stored once, but company projections expose only the authorized subset. A global metadata observation does **not** grant company-scoped readers source-wide access. Capture/financial jobs must be bound to an exact company.

Composite keys, foreign keys, RLS and runtime reauthorization protect APIs, job queues, caches, blob storage and historical views.

## 2. Temporal Database

Registry-recorded time is assigned by the server at the **authoritative commit boundary**, not trusted from a client-supplied timestamp. Source-effective time is recorded only when a source marker or its semantics are evidenced; otherwise it remains `NULL`. The time at which polling occurred must not be presented as the effective date of a change.

`AS KNOWN AT K` reconstructs what was known at knowledge time K. `AS EFFECTIVE AT V` with knowledge cutoff K reconstructs the effective state at V as it was understood by K. A late correction appends a new event with `supersedes`, never rewrites the previous history.

If polling sees A → B → A but no source history exposes the intermediate B, its precise occurrence is unknown. Report an appropriate gap/coverage limitation instead of inventing events.

## 3. API Contracts

**Connection registration and source OAuth:** Separate from ChatGPT OAuth.

**Enqueue rescan/report/reconciliation:** These are control-plane mutations requiring idempotency, CSRF protection and audit. A read-only source does **not** make job submission an immutable/read-only action.

**Read model/changes/job/result:** Require current scoped authorization plus the selected observed/accepted/version/time query. Possession of historical evidence is not perpetual authorization to disclose it.

**Request report:** Bind `recipe_id`, version/hash, source/company, permit reference, `scope_epoch`, typed parameters and private output policy. Forbid `command`, `sql`, `bsl`, `epf_bytes`, `arbitrary_url`, `password`, `connection_string`, and `force_validate`.

**Attest and accept:** Privileged commands with independently authenticated identity, exact artifact revision, claims and policy, real evidence foreign keys, and `expected_previous_head`. No public endpoint may simply write a `VALIDATED` status.

**Pause and revoke:** Scoped mutation with a reason, idempotency, epoch update and outbox cancellation. Revocation **before disclosure** blocks returning even an already computed result. Rollback never restores revoked grants.

## 4. Four JSON Schemas in the Companion Archive

- `schemas/model_event.schema.json`: `OBSERVED` event, nullable effective time, source/company scope level, coverage and gaps.
- `schemas/capture_request.schema.json`: typed request, recipe and permit, development/staging/production modes, safe parameters.
- `schemas/native_manifest.schema.json`: original artifact, source/recipe, evidence class and authority, parameters, hashes, completeness and attestation.
- `schemas/reconciliation_result.schema.json`: evidence/actual/model/policy references, Decimal values serialized as strings, numeric result separated from approval.

These were provided in the original chat archive and were **not automatically extracted on Windows** at the design checkpoint. Examples are synthetic. JSON Schema compliance does **not** establish authentic report provenance, a valid permit, or real authorization.

## 5. Where Each Claim Is Verified

| Claim | Authoritative verification |
| --- | --- |
| IDs, digests and Decimal representation | JSON Schema plus database contracts |
| Scope | Foreign keys, RLS, registry lookup and **current grants** |
| Permit | Actual policy, authorization epoch, time window and backend budget |
| Native report origin | Original bytes and qualified source/reporting procedure |
| Independent signer | Verified identity and separation of duties, **not** an untrusted JSON `signed_by` field |
| `MATCH` | Deterministic all-six-column and row-level computation under proven scope/cutoff/completeness |
| Production permission | Separate source-specific authorization and proof that capture has no business-data write effects |

Source fetch must not hold a long database transaction. Ingestion atomically writes a page, its events, cursor and outbox. Promotion transactionally validates the current head, evidence, policy and CAS. Every disclosure revalidates **current** access rights.

Append-only storage is not automatically protected from a database superuser. Audit anchors and privileged-role governance are separate security requirements.

## 6. Drive-Specific Clarification

The reviewed documentation for Drive `changes.list` states that page tokens **do not expire**. Do not confuse them with OAuth refresh tokens. Recovery tests should cover cursor loss, corruption, a change in identity or authorized corpus, not an invented periodic Drive cursor expiry.

Primary reference: [Drive changes.list](https://developers.google.com/workspace/drive/api/reference/rest/v3/changes/list).

Read-only/Viewer access does not guarantee revision-history API access. Never increase permissions or mutate `keepForever` merely to download historical revisions. Capture only genuinely accessible current bytes in a private immutable store and label their evidence basis and coverage honestly.

**Historical PASS and applicability to the latest revision are distinct states.**

## 8. Drive: offline port, consent and cursor (S7)

Not tools, not migrations, no wiring into Release 1 and no opening of the Drive capability: pure in-memory modules in `src/business_ai_gateway/phase2/`, without httpx/requests/socket/DB, without `os.environ` and file I/O, without importing `drive_http.py`, Release 1 or PDCC (AST check in `test_s7_boundaries.py`). Verified only against a scripted fake (IMPLEMENTED_UNVERIFIED); real Google behavior and G4 are not proven.

**Port `drive_port.py` (read-only).** `Protocol DrivePort` has exactly four async methods; there are no write, permission or keepForever methods by construction. All methods take `DrivePortIdentity(namespace, tenant, connection_id)` and `scope_epoch` first:

- `get_start_page_token(identity, scope_epoch) -> StartToken`
- `list_changes(identity, scope_epoch, page_token) -> ChangesPage(changes, next_page_token | None, new_start_page_token | None)`: exactly one of the two tokens (otherwise `PAGE_CONTINUATION_XOR_NEW_START_REQUIRED`); `to_drive_page(...)` adapts the page to the existing `DriveChangeProjector`.
- `get_file_meta(identity, scope_epoch, file_id) -> FileMeta(file_id, name, mime_type, parents, trashed, drive_id, shortcut_target, head_revision_id)`
- `list_revisions(identity, scope_epoch, file_id) -> tuple[RevisionMeta, ...]`

Port errors are only `DrivePortError` with a fixed `DriveErrorCode`: AUTH_REQUIRED, INVALID_GRANT, FORBIDDEN_HISTORY, NOT_FOUND, RATE_LIMITED, TRANSIENT, SCOPE_EPOCH_STALE; provider text is not passed through. A namespace is `account:<id>` or `drive:<id>`; one raw file id in two namespaces is two different objects. Ids, tokens and revision ids are byte-exact (no trim/case-fold); values are exact-type only (`str`/`int`/`datetime` subclasses are refused); timestamps must be timezone-aware and are converted to UTC. Completeness is decided by the calling module, not by the port. `drive_fake.py` (`FakeDrivePort`) is a scripted fake: pages, tokens, metadata with parents, revisions, forced errors (`invalid_grant`, 403 history forbidden, 404, 429), a call log, and a hook after N calls.

**Consent `drive_oauth.py`.** `ConsentManager` with `ConsentState`: NEW, CONSENT_PENDING, GRANTED, REVOKED, AUTH_REQUIRED; methods `begin_consent`, `complete_consent`, `revoke`, `mark_auth_required`, `snapshot`, `state_of`, `scope_epoch`, `is_authorized`, `consent_digest`. The `state` value is single-use (a replay is refused), the verifier is PKCE-style, the pending period is bounded on an injected clock, and a callback for another (tenant, connection) is refused. Tokens live only in `FakeTokenStore` (keyed by the ERP_MCP connection id; strings carry the prefix `FAKE-`; nothing from PDCC/Release 1 is accepted); they are not logged and do not enter the digest, `repr`/`str` or errors. Revoke deletes the tokens, increments the scope epoch and invalidates the cursors of the old epoch (old grants do not resurrect). `ConsentCode` codes: OK, INPUT_INVALID, IDENTITY_INVALID, SCOPE_REFUSED, GRANT_NOT_SUBSET, VERIFIER_INVALID, VERIFIER_MISMATCH, CODE_INVALID, STATE_INVALID, STATE_UNKNOWN, STATE_REPLAYED, STATE_EXPIRED, STATE_SOURCE_INVALID, TOKEN_INVALID, ALREADY_GRANTED, NOT_GRANTED, CLOCK_INVALID, EPOCH_EXHAUSTED, CAPACITY.

**Scope and membership `drive_scope.py`.** `evaluate_scopes(scope_names, risk_labels) -> ScopeEvaluation` yields a `ScopeClaim` (NARROW_FILE_SCOPE / READONLY_BROAD / BROAD) and an `Isolation` (FILE_GRANT_ONLY / APPLICATION_FILTER_ONLY / FOLDER_ISOLATED); a broad grant is never called folder isolation (`check_isolation_label` refuses with `ISOLATION_LABEL_REFUSED`), and to continue the risk label `BROAD_ACCEPTED` is required (`BROAD_REQUIRES_RISK_LABEL`). `ScopeCode`: OK, SCOPE_NAMES_INVALID, SCOPE_NAME_INVALID, SCOPE_UNKNOWN, SCOPE_SET_EMPTY, SCOPE_SET_TOO_LARGE, RISK_LABELS_INVALID, RISK_LABEL_UNKNOWN, BROAD_REQUIRES_RISK_LABEL, ISOLATION_LABEL_REFUSED, INPUT_INVALID. `resolve_membership(port, identity, scope_epoch, corpus, file_id, ...)` walks the parent chain up to the declared roots (depth and call budget are bounded, cycle-safe); `MembershipStatus` IN_SCOPE / NOT_IN_SCOPE, `MembershipCode`: IN_CORPUS, INPUT_INVALID, EMPTY_CORPUS, NAMESPACE_MISMATCH, FILE_UNRESOLVED, PARENT_UNRESOLVED, OUTSIDE_CORPUS, DEPTH_EXCEEDED, BUDGET_EXCEEDED, CYCLE, SHORTCUT_NOT_PROOF, TRASHED, PORT_REFUSED. `prove_scoped_read` and `observe_new_child_access` return an `AccessProof` PROVEN / NOT_PROVEN / DENIED only from a scripted observation (with a `ProofBasis`); access to new children is not assumed (G4 NOT_RUN).

**Baseline and cursor `drive_baseline.py`, `drive_cursor.py`.** The order is fixed and checked by `check_baseline_order(call_log)`: getStartPageToken -> persist token (CAS with fence) -> baseline listing -> catch-up from the recorded token -> terminal `newStartPageToken` -> LIVE. `CursorState`: UNINITIALIZED, BASELINING, CATCHING_UP, LIVE, GAP, AUTH_REQUIRED, RESNAPSHOT_REQUIRED. `DriveBaseline.run` returns a `BaselineOutcome`: LIVE, LIMIT_REACHED, BLOCKED, GAP, RESNAPSHOT_REQUIRED, AUTH_REQUIRED, LEASE_LOST, CONFLICT, RETRYABLE, REFUSED; `DriveRunMode` modes: INCREMENTAL, RESNAPSHOT_START, RESNAPSHOT_CONTINUE. The page and the cursor are committed together through the existing cursor CAS port (`DriveCursorStore.commit`) with a lease fence; a stale fence commits nothing; repeating a committed page is idempotent, the same id with a different digest is a conflict. Fail-closed `CursorReason` (through `ResnapshotTracker`): CURSOR_MISSING, CURSOR_EMPTY, CURSOR_CORRUPT, IDENTITY_CHANGED, CORPUS_CHANGED, SCOPE_EPOCH_CHANGED, TOKEN_NOT_FOUND, TOKEN_REPEATED, TOKEN_REGRESSED, TOKEN_MISSING, UNKNOWN_CHANGE_KIND, MEMBERSHIP_UNVERIFIED, PAGE_INVALID, AUTH_INVALID_GRANT, AUTH_REQUIRED, INCREMENTAL_BLOCKED, PAGE_LIMIT, ROW_LIMIT, START_TOKEN_INVALID, START_TOKEN_ORDER, INVALID_REQUEST, INTERNAL, LEASE_LOST, SCOPE_REVOKED, STALE_CURSOR, COMMIT_CONFLICT, INVALID_BATCH, INVALID_TRANSITION, RATE_LIMITED, TRANSIENT, PORT_UNEXPECTED, PORT_FAILURE. Cursor keys, candidates and dedup keys carry the namespace. As in section 6, a regular Drive cursor expiry is not invented.

**Revisions and membership `drive_revisions.py`, `drive_membership.py`.** `RevisionTracker.observe` / `record_attested` / `verdict` / `latest_verdict`: `ObservationOutcome` FIRST_SEEN, NEW_REVISION, DUPLICATE, OUT_OF_ORDER, REFUSED; `RevisionState` UNATTESTED, PASS_CURRENT, PASS_HISTORICAL, UNKNOWN; a new revision is a new UNATTESTED, the earlier PASS becomes PASS_HISTORICAL and does not count as latest (the attestation itself stays in `evidence_attestation.py`). `list_history(port, ...)` returns a `HistoryStatus` AVAILABLE / HISTORY_UNAVAILABLE / NOT_FOUND / CHECK_FAILED and a `HistoryCoverage` LISTED / CURRENT_ONLY / NONE; forbidden history yields HISTORY_UNAVAILABLE + CURRENT_ONLY, permissions are not raised, keepForever is not called. `MembershipChecker.check` / `authorize_disclosure` / `recheck_all` / `prepare_page` / `advance_epoch`: `MembershipVerdict` IN_SCOPE, SCOPE_ESCAPE_DENIED, NOT_IN_SCOPE, REMOVED, CHECK_FAILED; `PageStatus` PREPARED / REFUSED. A rename keeps the identity, a move inside the corpus is accepted after the parent chain is resolved again, a move outside, a shortcut to an external target and an unresolved parent are SCOPE_ESCAPE_DENIED without disclosure and without a candidate; deletion is a tombstone without a replacement by name/size/hash; revoke re-checks the cached membership before disclosure.

**Auth and hints `drive_auth_state.py`.** `DriveAuthHealth` with `AuthState` HEALTHY / AUTH_REQUIRED and `AuthCause` INVALID_GRANT / CONSENT_REVOKED / ACCESS_REJECTED. `TokenStatus` VALID / EXPIRED_REFRESHABLE / MISSING: an expired but refreshable token is refreshed and work continues; `invalid_grant` and revoke give AUTH_REQUIRED, a pause through `SourceStateMachine`, exactly one alert per transition (`AuthAlert`, without the token and provider text) into `AlertSink`, `AuthGuardedDrivePort` blocks all calls fail-closed, the cursor does not move (`run_poll` reads `committed_token`). `reconsent` -> `ReconsentResult` RECOVERED, NOT_REQUIRED, EPOCH_NOT_NEW, NO_CONSENT, EPOCH_MISMATCH, SCOPE_CHECK_FAILED, QUARANTINED, SEAM_FAULT (a new scope epoch and a fresh scope check are required). `HintIntake.accept_hint` -> `HintResult` ACCEPTED_NEW_JOB, ACCEPTED_COLLAPSED, REJECTED_INVALID, REJECTED_FOREIGN, REJECTED_STALE, REJECTED_PAUSED: a hint is accepted only with a matching channel/resource/owner token, only schedules a `PollJob`, is idempotent, carries no data and does not move the cursor. `run_poll` -> `PollStatus` COMPLETE, AUTH_REQUIRED, NO_CURSOR, PAGE_LIMIT, COMMIT_FAILED, PORT_ERROR; polling is complete without hints and without watch.

**Jobs API `jobs_api.py` (TC121-123).** Decision functions without a server: `decide_enqueue(ctx, request, session, csrf_token, capture_allowed=False)`, `decide_rerun(ctx, request, session, csrf_token, gate)`, `read_job(ctx, viewer, session, job_id)`, `read_result(ctx, viewer, session, job_id)` -> `ApiDecision(allowed, http_class, reason_code, next_action, correlation_id, ticket)`; `http_class` is one of {200, 202, 400, 401, 403, 404, 409, 429}. Annotations `ENDPOINTS` (`EndpointAnnotation(read_only, destructive, idempotent, open_world)`): ENQUEUE_JOB, RERUN, PAUSE_SOURCE, REVOKE_ATTESTATION - read_only=False, destructive=False, idempotent=True; READ_JOB, READ_RESULT - read_only=True; `DECISION_ENDPOINTS` maps each public decision function to an endpoint (PAUSE_SOURCE and REVOKE_ATTESTATION are annotations only, there is no decision function). The check order is fixed: session -> CSRF -> scope/epoch -> boundary -> idempotency -> dispatch. `CsrfGuard` compares the token through `hmac.compare_digest` over an exact `str` (test tokens carry the prefix `FAKE-`); `IdempotencyStore` uses the key `(tenant, actor, endpoint)` + `request_digest`, bounded by count and age on an injected clock; a replay returns the original outcome, a different digest is 409 IDEMPOTENCY_CONFLICT. Parameters are only typed ids per `_PARAM_SCHEMA` (`JobKind` RESCAN, REPORT, RECONCILIATION, CAPTURE, RERUN); there are no command/query/sql/raw/channel fields in signatures or request types. An operation passes through `canonical_operation` and `side_effect_boundary.evaluate`; a refusal is written to the append-only `RefusalLog`, a repeat with different letter case/whitespace/lookalike is refused with the same code and never reaches `FakeJobDispatcher`.

Deviations from the plan (facts from E1-E3): an expired session = 401 SESSION_INVALID; INTERNAL_REFUSED maps to class 400; the rerun-fence check runs inside the idempotency step; a full store gives 429 RATE_LIMITED; a CAPTURE job requires the typed fact `capture_allowed` (the permit logic of `capture_permit.py` is not duplicated); `request_rerun` takes an injected reader and current_epoch.

Known gaps: `RunRecord.differences` stores only measure names (ROW_DETAIL_UNAVAILABLE); row-level numbers of cards based on `Comparison` are consistent only with themselves; there is no real UI, HTTP, session/cookie or RBAC; `JobQueuePort` is not called and the PostgreSQL job constraints are not verified.

## 10. Operational readiness: capacity, audit, delivery, alerts, release, restore, export, retention (S9)

Not a server, not a scheduler, not migrations, no wiring into Release 1: pure synchronous in-memory modules `src/business_ai_gateway/phase2/` (stdlib and sibling phase2). All results carry `authority="EVALUATION_ONLY"`; status IMPLEMENTED_UNVERIFIED.
