## Purpose and boundary

This checklist defines what must be frozen and observed before the S12/S13 qualification phase can start. It does not approve a schema migration, enable writer admission, qualify a physical 1C write, or change S12/S13 or G0-G8 status. The existing read-only gateway stays read-only. Tests and database writes for qualification are restricted to disposable resources; the immutable DT, staging deployments, production bases, and unrelated project containers are excluded.

## Shared entry conditions

1. Sprint coding for the selected S12/S13 scope is complete and the exact source revision is identified. No qualification result may be carried across a later source change.
2. The S12 exact-revision GPT-PM clarification review is resolved against the document hash recorded in the correlated request. Any required contract edit gets a new review of the new exact revision.
3. S13 source-wide mutation, grant, trigger, helper, direct-DML, unique-conflict, and advisory/row-lock paths are reconciled against the selected common order. Database and reliability reviewers accept the full source path map before an additive fence migration is prepared. No migration is applied while this condition is open.
4. The functional and E2E agents derive a case-to-contract matrix from S12 §§2-6, S13 service and fence designs, the accepted stories, and the listed exit scenarios. Each case names its enforced boundary and the evidence artifact it must produce.
5. Every run records repository HEAD, migration hashes and order, environment identity, fixture/clone identity, exact command, result, and evidence path. Values, credentials, customer data, and private keys are not copied into chat or committed artifacts.

#### `S13-LEGACY-MUTATOR-CUTOVER-ACL-01` — read-only effective ACL capture query

```sql
BEGIN TRANSACTION ISOLATION LEVEL REPEATABLE READ READ ONLY;

WITH wanted_roles(role_name) AS (
    VALUES ('requester_role'), ('approver_role'), ('operator_role'),
           ('writer_role'), ('worker_role'), ('auditor_role'),
           ('checkpoint_role'), ('business_ai_private_writer'),
           ('private_writer_evidence_ingest'), ('business_ai'),
           ('business_ai_admin'), ('business_ai_app'),
           ('business_ai_control_api'), ('ledger_owner')
)
SELECT n.nspname AS schema_name,
       p.oid::regprocedure::text AS exact_signature,
       owner.rolname AS routine_owner,
       p.prosecdef AS security_definer,
       p.proacl::text AS explicit_acl,
       wanted.role_name,
       CASE WHEN role.oid IS NULL THEN NULL
            ELSE has_function_privilege(role.oid, p.oid, 'EXECUTE') END AS effective_execute,
       EXISTS (
           SELECT 1
           FROM aclexplode(COALESCE(p.proacl, acldefault('f', p.proowner))) acl
           WHERE acl.grantee = 0 AND acl.privilege_type = 'EXECUTE'
       ) AS public_execute
FROM pg_proc p
JOIN pg_namespace n ON n.oid = p.pronamespace
JOIN pg_roles owner ON owner.oid = p.proowner
CROSS JOIN wanted_roles wanted
LEFT JOIN pg_roles role ON role.rolname = wanted.role_name
WHERE n.nspname = 'change_ledger'
ORDER BY exact_signature, wanted.role_name;

SELECT default_owner.rolname AS default_acl_owner,
       COALESCE(namespace.nspname, '<all schemas>') AS schema_name,
       d.defaclobjtype,
       acl.grantee,
       acl.grantor,
       acl.privilege_type,
       acl.is_grantable
FROM pg_default_acl d
JOIN pg_roles default_owner ON default_owner.oid = d.defaclrole
LEFT JOIN pg_namespace namespace ON namespace.oid = d.defaclnamespace
CROSS JOIN LATERAL aclexplode(d.defaclacl) acl
WHERE d.defaclobjtype = 'f'
  AND (namespace.nspname = 'change_ledger' OR d.defaclnamespace = 0)
ORDER BY default_owner.rolname, schema_name, acl.grantee, acl.privilege_type;

COMMIT;
```
