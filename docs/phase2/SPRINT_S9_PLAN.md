## What this sprint can and cannot prove (stated first, on purpose)

G6-pre is defined as ACTUAL workload metrics, ACTUAL fault alarms and REPEATABLE recovery. All three need a real stand, real load, real fault injection and a real restore. S9 has none of them. What S9 delivers is the DECISION and ACCOUNTING logic those drills will use, so that when the operator runs them the arithmetic, classification, fail-closed ordering, dedup rules, rollback rules, restore-verification rules and export/retention rules are already fixed, tested over scripted inputs and reviewable. Consequences that must stay visible in every report:

- No number produced by an S9 module is a measurement of the product. Every capacity/alert/restore/export output is stamped `basis = SCRIPTED_OFFLINE_FIXTURE` and `authority = EVALUATION_ONLY`; a capacity report has no field that can express "capacity proven" and the readiness facade (E5) can never return a passed G6-pre.
- Passing tests prove that the pure functions classify and refuse correctly over the scripted inputs. They do not prove that PostgreSQL restores correctly, that a real replica/provider returns 429 the way the fake does, that an alert is delivered to a human, that real 1C stays responsive under load, or that a migration is additive on the real R1 schema.
- G6-pre stays NOT PASSED; G1, G4, G5 stay NOT PASSED; Release 2 stays NO-GO.

## Scope decision

S9 builds only what can be built and tested OFFLINE, as unwired, in-memory, synchronous reference modules (all NEW files in `src/business_ai_gateway/phase2/`; existing modules are touched only for a defect proven by a failing test, same rule as S6 E3, S6b, S7 and S8). The deliverable per story is the pure decision/accounting logic plus the fakes that make a fault observable: no load generator, no network, no real database, no real backup tool, no mail/pager/webhook, no deletion code and no 1C.

Design decisions fixed here (so reviewers can falsify them):

1. Measurement logic is separated from measurement. S9 modules compute percentiles, throughput, interference and verdicts FROM supplied samples; they never produce samples. A sample carries `basis`; a report built from samples whose basis is not an operator-supplied real-measurement reference is stamped `SCRIPTED_OFFLINE_FIXTURE` and is structurally unable to carry a `capacity_proven` flag (the field does not exist). A configured limit (budget, pool size, `max_sessions`) is never accepted as a sample (`CONFIG_LIMIT_NOT_CAPACITY`).
2. All outputs are derived, frozen, digest-bound and `EVALUATION_ONLY`. No function accepts a verdict, a status or a "passed" flag from the caller. Every decision returns a fixed `OpsReason` and, for refusals, an `OpsRefusal(reason, next_action, correlation_id)` with ids from an injected source, never derived from input.
3. Company/tenant ownership and entitlement come first (S8 review lesson). Every S9 function that reads or acts on tenant data takes `OpsScope(tenant_id, company_id, actor_id)` plus the injected `OwnershipPort` and `EntitlementPort`. Order is fixed and tested: structure -> entitlement of the actor for the company -> ownership of EVERY referenced object -> only then any read of the object. A foreign id and an unknown id produce the SAME `OpsRefusal` shape, same reason (`NOT_FOUND`), same fields, same observable port-call pattern, so existence is not an oracle. Kind mapping onto the existing closed S8 `OWNERSHIP_KINDS` (no edit of S8 files): sources, backends-by-source, alert subjects and legal holds use `source_id`; capacity reports, restore manifests, exports and retention policies use `report_id` (S9 mints these ids and registers them in the ownership port when it creates the object). Release-engineering decisions (E3) are platform-level: they carry no tenant data, take only typed enums, digests and counts, and are authorized by a separate injected `OperatorAuthorityPort.authorized(actor_id, action)`; a tenant actor can never trigger them.
4. Quotas are per tenant, never global (S8 review lesson). Every bounded structure (capacity samples, alert state, delivery-dedup records, hold ledger, export rows, manifest rows) is bounded PER TENANT with its own counters and eviction; filling one tenant's quota can neither evict, delay nor reveal another tenant's records, and a test fills tenant A to its cap and asserts tenant B is unaffected and the refusal for A does not mention B. The ONLY shared limiter is `PhysicalBackendBudget`, because the physical 1C backend IS shared by definition (TDD 11); fairness on top of it is a per-tenant sub-share so one tenant cannot consume the whole backend budget (`capacity_interference.py`, decision 8). No global cap hides inside a helper: a boundary test asserts no module-level mutable collection with a global size cap in the S9 modules.
5. Sessions, active clients, sources and physical backends are four separate axes (TC127). `LoadGrid` holds them as four distinct frozen types (`SessionCount`, `ActiveClientCount`, `SourceCount`, `BackendCount`) that do not convert to each other and cannot be passed in each other's place (exact-type checks; a test passes each where another is expected). A grid cell is the tuple `(sources, active_clients, sessions, backends, cache_state, discovery, workload_class)` taken from the fixed matrix in `TEST_PLAN` section 5 (sources 30/50/100/150; active clients 1/5/10/20/50/100; sessions 50/100/500/1000; cold/warm; discovery off/on; metadata/documents/balances/capture). A claim "N sessions" with no active-client dimension is refused `SESSIONS_NOT_ACTIVE_CLIENTS`; a cell with `sessions < active_clients` is `GRID_CELL_INCONSISTENT` (an active client has a session); a cell whose backend count is not declared is `BACKEND_COUNT_MISSING`. The R1 numbers (1000 sessions, pool 10, sidecar 4, fan-out 20/2) are different layers and are not accepted as inputs for any other layer.
6. Refusals are not throughput (TC128). Every request outcome is classified into one of a closed set `OutcomeClass`: `BUSINESS_OK`, `BUSINESS_ERROR`, `TIMEOUT`, `PROFILE_REFUSED`, `ACL_REFUSED`, `BUDGET_REFUSED`, `AUTH_REFUSED`. Throughput (business reads/sec) counts `BUSINESS_OK` only; refusals are reported in their own counters with their own latency distribution, never merged into the business percentile set; a run with a refusal fraction above a declared bound is flagged `REFUSALS_DOMINATE` and its throughput verdict is `UNRELIABLE_REFUSALS`. A fast profile refusal can therefore not raise the reported rate or lower p95.
7. Percentiles are exact and defined. Latencies are integer microseconds (exact `int`, not `float`); percentile is nearest-rank on the sorted exact values (documented, tested with known vectors for p50/p95/p99); fewer samples than a declared minimum for a percentile (for example p99 needs >= 100) gives `INSUFFICIENT_SAMPLES` instead of a number. Rates are `Decimal` with a fixed context; interference ratio is `(loaded_p95 - baseline_p95) / baseline_p95` exact, compared to the declared target (default 0.20) with the fixed result `WITHIN_TARGET` / `EXCEEDS_TARGET` / `BASELINE_INVALID`; the targets are parameters with the test-plan values as documented defaults and carry the label "proposed target, not a measured guarantee".
8. Background interference and budget (TC129): `plan_budget(policy, demand)` is a pure function that splits a backend slot budget between interactive and background classes: interactive has priority but background always keeps `min_background_slots >= 1` (starvation is refused as a policy: `BACKGROUND_STARVED`); capture = 1 per backend and writer = 1 per source are the conservative defaults (TDD 11); per-tenant sub-share bounds one tenant's use of a backend; the result lists granted/deferred demand with fixed reasons (`BACKEND_BUDGET_EXCEEDED`, `TENANT_SHARE_EXCEEDED`). The arithmetic is verified over a deterministic fake workload (scripted arrival tables on `FakeClock`); real interference on real 1C is NOT_RUN.
9. Audit is a gate BEFORE the effect and fails closed (TC130). `guarded_effect` writes an intent record through the injected `AuditSinkPort` first; if the sink is down, raises, times out (fake deadline on `FakeClock`), returns a malformed ack, or is not durable (ack without a sequence number), the effect callable is never invoked (call log asserts zero) and the result is `AUDIT_UNAVAILABLE`. After the effect, a completion record is written; if THAT write fails the effect has happened and cannot be undone, so the outcome is the explicit `AUDIT_COMPLETION_PENDING` (a visible reconciliation obligation recorded in a bounded per-tenant "unaudited effects" list that alerts on), never a silent success and never a retried effect. Read-only decisions that do not change state are not gated, and the classification of which operation needs the gate comes from the existing `side_effect_boundary` registry, not from a new list.
10. Delivery is at-least-once with exactly-once EFFECT through digest de-duplication (TC131). `delivery_replay.py` models the publish loop over outbox-shaped records: a delivery attempt returns `DELIVERED`, `RATE_LIMITED(retry_after)` (the 429), `NETWORK_FAILURE` or `DUPLICATE_ACK`; the dedup key is `(tenant, source, connection, event_id)` with the stored `event_digest`; the same id with the same digest is a replay and publishes nothing again; the same id with a DIFFERENT digest is `EVENT_DIGEST_CONFLICT` and is quarantined, never overwritten; a 429 or network failure re-queues with `backoff_delay` and bounded attempts, never advances the cursor past an undelivered event, and a replica (second worker with a different lease owner and an older `claim_generation`/fence) cannot publish or mark delivered (`STALE_CLAIM`). The scenario test runs two workers and an injected sequence of 429/network faults and asserts: every event published exactly once to the fake sink, none lost, order within a connection preserved, per-tenant isolation, and a bounded attempt count ending in explicit `FAILED` (not infinite retry).
11. Alerts are state machines with hysteresis, observable on both edges (TC132). `AlertRule(kind, threshold, for_duration, recover_threshold, recover_duration)` over samples at an injected clock; states `OK -> PENDING -> FIRING -> RESOLVED -> OK`; exactly one `FIRED` and exactly one `RECOVERED` event per episode (flapping inside hysteresis creates no second event); a missing sample stream is itself an alert condition (`NO_DATA`, never "OK because silent"); the alert sink is a fake with an induced delivery failure that surfaces as `ALERT_DELIVERY_FAILED` and a retained undelivered event (an alert that failed to deliver is never marked sent). Rule kinds map to the TDD list: audit unavailable/lag, cursor lag, outbox lag, failure ratio, unaudited-effects non-empty, restore verification failed. Alert state and events are per tenant (and a separate platform scope for platform rules); one tenant's samples cannot fire or resolve another tenant's alert. Real delivery to a human is NOT_RUN.
12. Migration steps are classified from a typed description, not from parsing arbitrary SQL in a decision path (TC133, TC134). `MigrationStep(phase: Phase, kind: StepKind, schema: SchemaName, object_class: ObjectClass)` where `Phase` is EXPAND / SHADOW / SWITCH / CONTRACT, `StepKind` is a closed enum (CREATE_TABLE, CREATE_INDEX, ADD_NULLABLE_COLUMN, ADD_ROLE, GRANT, ADD_FUNCTION, FEATURE_FLAG, DROP_*, TRUNCATE, ALTER_TYPE, RENAME, REVOKE, DELETE_ROWS ...), and `classify_step` returns `ADDITIVE`, `SWITCH_ONLY`, `CONTRACT` or `DESTRUCTIVE`; any step touching an R1 schema/object class, or of an unknown kind, is `UNCLASSIFIED` and denied. Separately, an offline guard test reads the real `db/phase2/001..003` SQL text (tests may read files; modules may not) and asserts that every statement is `CREATE ... IF NOT EXISTS`/`CREATE OR REPLACE`/`GRANT` inside the `living` schema and that no statement references an R1 object, so the "additive" claim is checked against the actual migration text, not only against a typed table. A migration rehearsal is modelled as `plan_rehearsal(steps, applied_versions)` -> ordered plan, validated against `living.record_migration(version, requires)` semantics (requires satisfied, no gaps, idempotent re-apply); the real rehearsal on a disposable copy of the R1 database is NOT_RUN.
13. Shadow compatibility is a digest comparison, not a promise (TC133). `ShadowObservation(operation_id, r1_digest_before, r1_digest_after_expand, r2_shadow_digest)` over a scripted R1 corpus; `compare_shadow` returns `R1_UNCHANGED` when every R1 digest is identical before and after the expand step, `R1_REGRESSION` (with the operation id, which is a typed fixture id, never free text) on any difference, `SHADOW_DIVERGENCE` when R2's observed-only shadow output differs from R1 for a comparable operation (a finding, never an automatic promotion), and `SHADOW_INCOMPLETE` when an expected operation has no observation (absence is not a pass). R1 behavior itself is read only through supplied digests; no Release 1 import.
14. Rollback is a decision with a fixed denial set (TC134, TC135). `decide_rollback(plan, release_state, grants, authority)` allows only: flip the feature flag/route back to a version compatible with the CURRENT live schema. It refuses with fixed codes: `ROLLBACK_DESTRUCTIVE_DENIED` for any step that drops, truncates, renames, deletes or narrows data or schema (checked via `classify_step`, not by a name list); `ROLLBACK_HEAD_INCOMPATIBLE` when the live schema contains an accepted head/acceptance record the older version cannot read (blocked, not forced); `ROLLBACK_WINDOW_OPEN`/`CONTRACT_NOT_ALLOWED` for contract cleanup before the rollback window has elapsed on the injected clock and without a separate approval; `NOT_AUTHORIZED` without the operator authority. Rollback never executes anything: it returns a plan digest, and applying it is operator-owned.
15. Rollback never resurrects rights or evidence (TC135). The post-rollback effective grant set is computed from the CURRENT grant registry at rollback time, never from a snapshot taken at switch time: `effective_after_rollback = current_grants` filtered by non-expired credentials and attested evidence via `AttestationStore.check_current`; a grant revoked or an attestation revoked after the switch stays revoked; expired credentials stay expired; the switch-time snapshot may only be used to REPORT what differs (`RESURRECTION_BLOCKED` entries carry typed ids only), never to restore. A test builds the exact adversarial sequence: grant G issued, switch, G revoked, rollback, assert G not effective, a second rollback and a clock regression do not resurrect it either.
16. Restore verification is a comparison of two manifests, not a restore (TC136). `build_manifest(rows)` builds a `RestoreManifest` from the in-memory registry (per table: row count, ordered row digests via `canonical_digest`, primary keys, FK edges, accepted heads `(model_key, revision_id, version)`, outbox event sequences, attestation heads) and `verify_restore(source_manifest, restored_manifest, fk_catalogue)` returns per-check results with fixed codes: `RESTORE_COUNT_MISMATCH`, `RESTORE_DIGEST_MISMATCH`, `RESTORE_FK_ORPHAN` (every child row's parent exists in the restored set, using the catalogue mirrored from the real SQL), `RESTORE_HEAD_MISMATCH` (head `revision_id` exists in observations and `version` matches), `RESTORE_SEQUENCE_GAP` (event/outbox sequence contiguous, no duplicate), `RESTORE_ATTESTATION_STALE` (restored attestations are re-checked as CURRENT against the current rights, never trusted from the backup), `RESTORE_SCOPE_FOREIGN` (a row of another tenant in a tenant-scoped restore). An empty/short/partial manifest never verifies (`RESTORE_INCOMPLETE`). The only real restore proof in the repository stays `test_g1_restore.py` (needs the disposable container); a repeatable operator-run restore rehearsal is the G6-pre evidence and is NOT_RUN here.
17. Export is deny-by-default and formula-safe (TC137). `build_export(scope, request, rows, policy, ownership, entitlement)`: after the decision-3 checks, only rows whose `(tenant, company)` equals the scope are admitted (any foreign row in the input is DROPPED with the opaque `HIDDEN_BY_SCOPE` flag, no count, no id); every column must be declared in a fixed `ExportColumnPolicy` (`PUBLIC`, `MASKED`, `HASHED`, `DENIED`), an undeclared column is `COLUMN_UNCLASSIFIED` and not exported; masking is a fixed deterministic function (length-preserving masking is NOT used because length leaks; masked cells use a fixed token or a keyed-less digest prefix by policy); formula injection: after NFKC and stripping of leading whitespace/control/zero-width characters, a cell beginning with `=`, `+`, `-`, `@`, tab or carriage return (including full-width and lookalike forms) is neutralized with a leading apostrophe and the neutralization is counted, applied to values AND header cells; CSV/ZIP bomb style limits (row/cell/byte caps, per tenant); formulas are never evaluated; secrets and credential-shaped values are `DENIED` by a fixed detector. The export result carries `export_digest` and the policy digest, and is `EVALUATION_ONLY`.
18. Retention and legal hold only DECIDE, they never delete (TC138). There is NO delete function, no `shutil`/`os.remove`/SQL anywhere in S9. `RetentionLedger` is append-only: policies (`retention_class`, `min_age`), holds (`place_hold`/`release_hold` with requester and a DIFFERENT approver, bounded text-free reason code from a closed enum), and approvals (`DeletionApproval` bound to the digest of the exact object list and policy version, with expiry). `decide_deletion(request)` returns `DELETION_ALLOWED_PLAN` only when ALL hold: object owned by the scope, retention elapsed on the injected clock, NO active hold (a hold on the object, its tenant-scope or its source blocks), a valid unexpired approval whose digest matches the exact object list, and the approver is not the requester. Anything else is a fixed refusal (`HOLD_ACTIVE`, `RETENTION_NOT_ELAPSED`, `APPROVAL_MISSING`, `APPROVAL_EXPIRED`, `APPROVAL_DIGEST_MISMATCH`, `SELF_APPROVAL`, `OBJECT_NOT_OWNED`). The positive answer is a plan with `executed=False` as a constant; actual deletion is a separate, operator-authorized, unrecoverable-action gate outside this package (global rule: deletion is operator-only). Releasing a hold is itself audited through the audit gate (decision 9) and a hold placed after an approval invalidates that approval at decision time.
19. G6-pre readiness is a checklist of missing evidence, not a verdict (E5). The facade lists the required actual-evidence slots (workload metrics per grid cell, fault alarms fired and recovered on staging, repeatable restore rehearsal, migration rehearsal on a copy, R1 shadow regression on staging, retention/hold policy approval) each with status `NOT_RUN` unless an `OperatorEvidenceRef` (typed id + digest + environment label + head) is supplied, in which case the slot becomes `EVIDENCE_RECEIVED_UNVERIFIED` (S9 does not read or validate the artifact). `g6_pre_passed` does not exist as a field; the facade output states the NOT_RUN set verbatim.

## Known gaps stated up front (honest limits, not hidden)

- The existing capacity evidence is the S4b drill on a disposable container (`CAPACITY_DRILL.md`: "measurement, not a guarantee"); the S9 grid, percentile and interference logic has never seen a sample from a real 1C or a real staging deployment. Target values (500 ms, 500 ms, 20%) are proposals from the test plan, not measured SLOs; real SLOs/stop criteria/hardware are approved by the operator before load.
- `PhysicalBackendBudget` is a single-process reference; the TDD requires a distributed atomic backend for production. S9's per-tenant sub-share is likewise single-process. Multi-process/replica correctness of budgets, leases and fencing is covered only by the existing PostgreSQL tests (`test_g1_concurrency_mp.py`, NOT_RUN without the container) and is not extended.
- Delivery/alert/audit fakes script the faults the plan names (429, network failure, duplicate ack, sink down, slow, malformed ack). Real provider/replica behavior (partial writes, reordering across replicas, clock skew between hosts, a sink that acknowledges and then loses data) is not modelled beyond what the scripted fakes encode; a durable-ack-then-lost sink cannot be detected offline.
- The FK catalogue and the SQL text guard are tied to migrations `001..003`. Later migrations must extend the catalogue; the parsing test fails on drift in either direction but cannot prove the catalogue covers constraints implemented as triggers.
- Restore verification compares manifests built from in-memory rows. It does not prove that `pg_dump`/`pg_restore` (or any backup tool) produces a faithful copy, that sequences/ACLs/RLS survive, or that restore time meets an RTO; `test_g1_restore.py` is the only real restore proof and needs the disposable container.
- Migration classification works on typed step descriptions; the additive claim for the real R1 schema (which this branch intentionally does not import) can only be rehearsed on a disposable copy of the R1 database by the operator. R1 behavior enters only as supplied digests.
- Masking/tokenization uses a fixed deterministic policy without a managed key; real key management, DLP coverage of unstructured content and privacy classification of every column are not addressed. Formula neutralization targets spreadsheet formula injection in CSV/XLSX cells; it does not sanitize other downstream consumers.
- Legal hold and retention decide only; they do not enforce. The real enforcement point (storage/DB layer, backup expiry, replica copies) is out of scope and unwired; a decision "deletion plan allowed" is not an authorization to delete and deletion stays an operator-only action.
- Actor authorization is an injected allow/deny fact (`EntitlementPort`, `OperatorAuthorityPort`); the real RBAC, operations separation and four-eyes workflow are not built.

### E2 (audit gate, delivery replay, alert rules)
- `audit_gate`, `delivery_replay` and `alert_rules` take a non-blocking try-lock on `TenantSlotCounter(1)`; a busy lock returns `INTERNAL_REFUSED`.
- Slots are never freed inside S9 (there is no delete path).
- Alert state `RECOVERING` replaces `RESOLVED`.
- An unclassified operation is refused with `UNCLASSIFIED`.
- The audit timeout is checked on the fake clock after the sink call returns, not preemptively.
- The fence check and the sink call are not atomic; the sink must answer `DUPLICATE_ACK` for a repeated record.
- `NO_DATA` fires only on `tick`, never on `observe`.

### E3 (release migration and rollback)
- Typed kinds `REPLACE_*`, `HARDEN_PRIVILEGES` and `SET_OWNER` are classified ADDITIVE for statements the real SQL contains outside the plan's narrow set: `DROP TRIGGER/POLICY IF EXISTS` before `CREATE`, conditional `DROP FUNCTION`, `CREATE TRIGGER/POLICY`, RLS enable/force, `ADD COLUMN IF NOT EXISTS`, `CREATE ROLE living_*`, owner/security definer, `REVOKE`, `ALTER DEFAULT PRIVILEGES`.
- Finding: the first `ALTER DEFAULT PRIVILEGES FOR ROLE living_owner` in migration 003 has no `IN SCHEMA` clause (it is not schema-scoped).
- `plan_rehearsal` takes `MigrationUnit` rather than the plan's step list.
- The rollback window uses the injected clock; a clock regression only lengthens the window.

### E4 (restore, export, retention)
- Attestation rows carry extra columns `policy_version` and `policy_digest`.
- Signatures take `source_ids`, `ownership`, `entitlement` and `ids`.
- `RetentionLedger` holds the ports.
- Hold release needs another approver plus `audit_fn`; a stalled release stays an active hold.
- The restore manifest is only as honest as the rows the caller supplies.
- The secret detector is heuristic and has false positives.
- `HASHED` columns are unkeyed hashes.
- Export builds text cells only.
