# S11 test-design package: invariants, scenarios, coverage gaps, sprint stories (2026-10-12)

Status: DRAFT for GPT-PM review. Authored by the `functional-test-reviewer` agent (read-only, document-derived) and recorded here by the main session; no code and no runtime evidence exist behind it. Sources: plan revision 5 (sections 4, 5, 12, 16), the S11 decision records and the CT14 spike record. The source inventory was not read by the author. Story ids below are an ASSUMPTION (the plan has no per-sprint story ids). No test is run during coding: every listed test is authored and run after the sprint's coding is complete, with data fixtures and no mutation of product code.

Conventions: "zero port calls" = the write-port call counter; "B snapshot" = before/after read of the target base (document count by canonical key with a year filter, registrar movement rows over all recorder registers, data version, posted flag); "ledger code" = the refusal code persisted in the ledger. Every negative control needs a positive twin (the same fixture without the distortion must succeed), otherwise an always-red check passes.

### Scenario flags

- E2, E33, E23, E34, E38 (contract parts): not executable as written, because CT2 speaks of an appended provenance row on update while the S11 records say there is no mechanism and the contract update is out of the first S12 freeze. Amend to "contract: deferred" or measure a mechanism first.
- E7, E27, E40: the "digest equal or no proposal" disjunction is vacuous; need per-file expected outcomes and a positive twin.
- E13: only the B snapshot and zero port calls are real; E15: add ledger code and snapshot.
- E16, E35, E20, E24: U-only, in-memory races and fingerprints prove nothing at the real boundary.
- E34, E44: the "forced termination safe" branch is untestable now (CT14 item 9 INCONCLUSIVE, forced termination DENIED); the test must assert zero termination invocations and base-wide hold on the unsafe branch; item 10b is INCONCLUSIVE so "other target continues" is untestable; mark safe-branch cases NOT_RUN or BLOCKED_BY_CT14; the session list measured with one connection proves nothing about foreign sessions; the OData non-cooperating writer assumption needs a COM or interactive writer instead.
- E36: if the checkpoint store is co-located with the DB, the DBA trust boundary is not exercised.
- E45: if the illegal-transition set is generated from the implemented table it is a tautology; use a literal list transcribed from CT10.
- E12: the "marker unchanged" case depends on the marker mechanism and on a content-hash store existing first.

## B. Coverage gaps against requirements

S11 requirements and threat rows:
1. S11-A and TM16: no scenario. Needed (new id, ASSUMPTION `T-S11A`): with an approved change in the ledger, WRITE or POST through `side_effect_boundary.evaluate`, `capture_permit`, `jobs_api` and `connector_sdk` stays denied; the READ regression set stays unchanged.
2. S11-B: no scenario. Four durable states (lost completion acknowledgement, failed effect, unknown outcome, duplicate) must be distinguishable and none may read as VERIFIED; completion obligations must survive a restart.
3. S11-C and TM8: partly covered by E20 and E32. Missing: re-read at both claim and pre-effect with the company in scope; four change points x four change kinds; the residual window after the last re-read is declared, not tested.
4. S11-D: no scenario. A six-column MATCH, an ORIGINAL_INTACT card or an audit acknowledgement must each yield NOT_VERIFIED; expected empty movement set for a draft or catalogue update.
5. TM18-TM20: TM19 needs a restored-copy fixture at the lane level (E35 is U-only); TM20's periodic rights-matrix read has no scenario.
6. TM15: "no forced-termination call is made" is not stated in E34 or E44.
7. TM5, TM12, TM6: covered by E3, E28, E12, E21 but all depend on the undecided marker mechanism.

Contracts:
- CT1: no scenario for the test-lane auto-policy exception, write-token replay by token id and short expiry, or approver role re-check before the effect.
- CT2: resolution conditions (a)-(d) are not tested one by one; the max age (5 attempts over 15 minutes) to TRIAGE_REQUIRED has no scenario and needs an injectable clock (ASSUMPTION); the no-request-id second layer is implicit; post and unpost recovery is covered only for the after-post crash window in E18.
- CT3: the safe-termination branch, item 10b and foreign-session observation are unmeasured; no test pins the base-wide hold default.
- CT4: staging DENY, unknown-class DENY and restored-epoch refusal at lane level.
- CT5: ANCHOR_GAP and key rotation; the undetected window must be labelled KNOWN_LIMIT.
- CT6: one oracle document shape; the import-graph test needs an explicit story.
- CT7: dependent documents and closed period unmeasured; ROLLBACK_REFUSED differs from FAILED_VERIFY.
- CT8: only the purchase receipt has proven effects.
- CT9: REVOKE versus STOP_ADMIT versus STOP_EFFECTS are not distinguished in E11 and E41.
- CT10: no test for the single error-code registry (uniqueness; new codes as enum members; `safe_errors` extension).
- CT11: malware handling, per-field provenance and "the model may not call apply on file-derived instructions" have no assertion.
- CT12: framing denial, cookie flags, re-authentication and second confirmation are not enumerated in E39.
- CT13: the per-operation matrix needs explicit sub-cases (re-post, correction delta, unpost without refund, pre-existing draft full gross, contract update with zero amount, mixed-currency refusal).
- CT14: items 9, 10b, 13 and the custom-role part of item 12 are INCONCLUSIVE; H4 has no scenario; E47 must run on the actual CT14 record.
- CT15: shutdown drain, the 60 s alert target, queue bound 20 and read priority are covered only by E44 prose.

Cross-cutting prerequisites with no owner: a clone containing a dependent document, a period-closed setting, a second organization, a blocked-call harness (exclusive lock held by a second session), and a wrapper around the real port for fault-after-commit. The marker mechanism and durable provenance gate E2, E12, E18 and E33.
