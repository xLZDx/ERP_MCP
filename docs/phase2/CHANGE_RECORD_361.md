## What was done

- The repository's inventory script reads the clone through the local DPAPI helper and local paths, so it cannot run
  on Ivan's host. A PowerShell equivalent was written for the host: it decrypts the stored clone login in process
  with the existing `onec_admin.dpapi` blob, connects through `V83.COMConnector`, and prints only metadata names:
  configuration name and version, platform version, and the attribute and tabular-section names of the document
  `ПоступлениеТоваровУслуг`. It reads no business rows, checks no rights, creates no 1C objects, writes no files
  and never prints the login. The file is ASCII only (Cyrillic names as `\u` escapes, generated by a script) so
  encoding on the host cannot change them; its output also escapes non-ASCII characters because the SSH console code
  page garbles them.
- Two PowerShell behaviors had to be handled: functions unroll enumerable COM objects (fixed with the comma operator)
  and the configuration `Name` and `Version` properties need their Russian names through `InvokeMember`.
- The script was copied to `D:\1c\mcp\ct14_metadata_inventory_ivan.ps1` on Ivan's host over strict SSH and run once
  per fix while debugging; the final run succeeded.
